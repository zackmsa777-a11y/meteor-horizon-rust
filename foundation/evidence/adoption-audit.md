# Solstice foundation audit and bounded adoption

Read-only reference audited at PointOfPressure/solstice-client commit 2b11af4dfae7b08f9faa65d6fd3f4ab7b32030d1, version 0.7.0. Its manifest pins Horizon ba6344a59cb9e755b730dcf02285fc0d33b97d3c and Mixins 0d6b103c70633d8fd9443d8d0acd3aadaacedb06 (the latter is transformer 0.5.0, verified from its Cargo.toml). Our adoption pins remain pristine b76ae35f5b9b2d82c0e6818fc0ef93bb5277ec73 and Mixins 0.6.0 cb1ad23022392d88f006cf94cbf6552a73f5df12, retaining own-crate capability and existing build evidence. Root's unchanged-upstream compatibility probe resolved all 23 original hooks/10 support modules and compiled against our pin; those results do not verify the adapted candidate's runtime behavior.

Upstream registers 89 distinct concrete module records: Combat19, Movement24, Player17, Render19, World10. Catalog construction is runtime.rs::defaults plus combat/render/player/world defaults. Each catalog name has a corresponding code path; I found no explicit TODO/unimplemented/empty registration. Registration and existing operations do not establish full Meteor source fidelity or live behavior. Our adapted catalog has87 because Auto Respawn and Fast Break are reserved for the friend's work and are excluded from registration/dispatch, without substitute stubs.

Useful foundation code includes the native category/panel/slider/menu model, command parsing and settings persistence, inventory/menu operations, packet/placement/target adapters, the camera and world-overlay operations, and normal declarative .hnmod support-module/HEAD/RETURN packaging. The public identity is Meteor Horizon; original Solstice internal module names and the complete PointOfPressure MIT copyright/permission notice remain in normal bundle data. Packager provenance tracks both upstream Git bytes and the copied working-tree bytes. The original pack.py did not include its LICENSE, so adoption packaging explicitly corrects notice inclusion.

Critical source hazards addressed by the candidate:

- STATE/CS/RS/PS/WS and engine flags were global with no owner or observed-world cleanup. The adaptation keeps this bounded architecture but anchors its one active window with a stable Weak<Window>, verifies Arc identity without Game addresses, reloads config on owner switch, and resets transient state on owner switch, native disable or observed player/title world leave. Simultaneously active windows are still unsupported; same-window replacement without an absent-player interval lacks a stable session identity.
- Outgoing packets, camera/turn, Reach, Timer/NoSlow and worker Xray could bypass native disable after tick/HUD returned early. Actual role/on/window gates and explicit reset APIs now clear packet spoof/hold state, Reach, flight/Step, camera, Fullbright, Xray and transient family state. Timer/NoSlow are client-thread local; worker Xray remains global and is cleared/rebuilt on observed transitions.
- Packet hooks may be reentrant while STATE is held. The owner gate is a separate short-lived TLS Weak snapshot and GUI read gates are atomic snapshots updated after State mutations. Readonly engine guards do not lock STATE. Cleanup drops State and family guards before native callbacks, and marks transition flags before callbacks to prevent recursive cleanup.
- The old menu rendered and processed deferred close inside ordinary F1-sensitive native HUD. The separate raw hud_layers compositor now draws it regardless of F1 while retaining the outer native dialog/debug layers. Synchronous close plus a short input latch prevents closing Escape from opening Pause. The narrow layout uses category tabs/one scroll column, and widgets reflect actual visible controls. Open/close clears held native keys/buttons/toggle mappings and accumulated look. Focus/disable/leave cleanup remains subject to live tests.

Retained upstream differences must remain visible in product claims: Zoom defaults to factor4 and fixed turn0.3 rather than Meteor's cubic easing/default6; Air Jump checks literal Space and writesY0.42 rather than rebound keys/maintain-level/native jump sequencing; High Jump rewrites post-gravity velocity with a fixed0.42 formula and default multiplier2 rather than Meteor's attribute/block-factor/additive-boost semantics/default1; Auto Jump injects Space only while moving and omits Jump/LowHop/JumpIf fields. Auto Tool lacks the retained core's full source tool filter/durability/enchantment/swap policy; Auto Eat uses prototype food and one hunger threshold. These are actual implementations with narrower/different behavior, not full parity. The verified four-module Meteor policy path remains in its separate frozen bundle/public native tree; neither it nor the retained core was rewritten by this adoption.

The GUI remains upstream ASCII key-name search and keyboard-only simple binds; text-list settings are explicitly disabled in the GUI and edited by the actual .set command. Full Unicode editing, modifier/hold binding parity, keyboard/controller menu navigation, custom fonts and complete Meteor GUI/theme parity are not claimed. The existing .t/.set/.bind/.modules/.settings/.help interfaces are production commands, not debug-only verification shortcuts.

The production source snapshot is held at the hashes in source-freeze-report.json. New checks prepared in actual generated host sources cover catalog exclusions/default bounds, transient reset preservation, lock-free GUI gate reentry/close latch, packet cleanup and narrow hit rectangles; Timer/NoSlow include client-thread separation tests. Root owns official transformation, Cargo, isolated runtime checks and publication. This agent executed no Cargo/game/official transform for the adoption candidate.
